# V2.5 hardware — keyboard test + threshold buttons

The [V2](../v2-keyboard-test/HARDWARE.md) rig with two buttons added. Keyboard,
resistors, polarity and speaker are unchanged; this page covers the delta.

## Pin map (changes in bold)

| Pin | Direction | Role |
|---|---|---|
| A0–A6 | analog in | 7 fruit touch keys, each with a **220 Ω pull-up to +5 V** |
| D8 | out | speaker / passive buzzer (one fixed note per key, C3..B3) |
| **D10** | **in** | **THRESHOLD + — raises the touch threshold (step 5, auto-repeat)** |
| **D11** | **in** | **THRESHOLD − — lowers it** |
| D0/D1 | UART | **serial monitor at 9600, on** (V2's `Serial.begin` is commented out) |
| 5V / GND | — | rails; the player holds a clip on **GND** |

## The two buttons

Active-**LOW**, straight to GND, using the AVR's internal pull-ups:

```
 D10 ──[button]── GND        (THRESHOLD +)     pinMode(INPUT_PULLUP)
 D11 ──[button]── GND        (THRESHOLD −)     pressed == LOW
```

**No external resistors.** This differs on purpose from V3/V4/V4.5, where the
buttons are active-HIGH to +5 V and each needs its own 10 kΩ pulldown: those are
part of the finished instrument, this is a bench rig you wire up in a hurry.

⚠️ Consequence for the browser build: Velxio does not model the internal pull-ups
(an active-low pin with no pull-up floats near 0 V in its solver and reads
permanently pressed), so [emulation/keyboard-test.yaml](emulation/keyboard-test.yaml)
adds an external 10 kΩ per button. On real hardware they are not needed.

## Threshold behaviour

| Constant | Value | Meaning |
|---|---|---|
| `touchThreshold` | starts at **1019** | V2's hardcoded number, now a variable |
| `THRESHOLD_STEP` | 5 | per press and per auto-repeat tick |
| `THRESHOLD_MIN/MAX` | 0 / 1023 | clamped; a press at the limit prints nothing |
| `REPEAT_DELAY_MS` | 400 | hold this long before ramping starts |
| `REPEAT_EVERY_MS` | 120 | one step per this interval while held |
| `BUTTON_DEBOUNCE_MS` | 40 | contact debounce |
| `READOUT_EVERY_MS` | 500 | live readout period |
| `TOUCH_WHEN_BELOW` | `true` | `true` = 2019 wiring (touch drags down), `false` = 2026 wiring (touch pushes up) |

## Sensing

Unchanged from V2: 4-sample average per key, `average <= touchThreshold` counts as
touched, with pins biased high through the 220 Ω pull-ups and the body pulling them
down toward the GND clip. The physics and the 2019-vs-2026 polarity table are in
[../../docs/HARDWARE.md](../../docs/HARDWARE.md).

The one behavioural change: detection is **edge-triggered** per key, so a held
lemon plays its note once instead of re-firing every loop.
