# V4 hardware — lemon piano with the water pump

Reconstructed from [firmware/src/main.cpp](firmware/src/main.cpp), the surviving
Fritzing diagram ([../../docs/keyboard-schematic.fzz](../../docs/keyboard-schematic.fzz))
and the 2019 photos. ⚠️ marks what the code alone cannot settle.

## Pin map (Arduino Nano)

| Pin | Direction | Role |
|---|---|---|
| A0–A6 | analog in | 7 lemon touch keys, left → right, **220 Ω in series** to the pin |
| D2 | out | **RED LED** — wrong note (220 Ω to GND) |
| D3 | out | **GREEN LED** — correct note (220 Ω to GND) |
| D4 | in | **GAME SELECT** SPDT switch — HIGH at boot/restart ⇒ game 1, LOW ⇒ game 2 |
| D5 | out | **RELAY 1** (`RELAY_1`) — water-pump pair |
| D6 | out | **RELAY 2** (`RELAY_2`) — water-pump pair |
| D7 | in | **RESTART** button, active-HIGH (+ 10 kΩ pulldown) |
| D8 | out | **passive buzzer** — key notes, victory and death tunes |
| D13 | out | on-board LED, lit while `buzz()` bit-bangs a melody note |
| 5V | — | **hand-held alligator clip** (the player closes the circuit) |

`pumpOff()` is defined as `RELAY_1 LOW` + `RELAY_2 HIGH` and is set **before**
`pinMode(OUTPUT)`, so the pump cannot twitch during boot (TODO #2).
⚠️ Relay-module polarity (active-HIGH vs active-LOW) is inferred from that
initialisation; a different module may need the levels swapped.

## The sensing inversion (V4's real innovation)

```
 5V ──[hand-held clip]── player ── 🍋 lemon ──[clip]──[220 Ω]── A0..A6
                                                            (pin otherwise floating)
```

- **Idle:** the pin floats and reads near 0 (mains-coupled noise only).
- **Touched:** 5 V → hand → body → lemon → pin. Skin + lemon drop most of the
  voltage, but the reading rises well above the calibrated threshold.

```cpp
if (analogRead(i) > keyThreshold[i]) { /* key i touched */ }   // threshold = baseline + 100
```

`calibrate()` samples each key's floating baseline at boot, replacing the 2019
"raise SENSITIVITY to 170 when on a laptop charger" constant. ⚠️ There are no
pull-downs in the code's model; if ghost notes appear, add ~1 MΩ from each analog
pin to GND (calibration then measures a cleaner baseline). Making that margin
noise-adaptive — and tunable from two buttons, on a board without the pump — is
what [V4.5](../v4.5-margin-buttons/HARDWARE.md) is.

The full 2019-vs-2026 polarity comparison lives in
[../../docs/HARDWARE.md](../../docs/HARDWARE.md).

## Feedback + actuator stage

```
 D2 ──▶|──[220 Ω]── GND         (red   = wrong)
 D3 ──▶|──[220 Ω]── GND         (green = right)
 D5/D6 ── relay module ── water pump      (1 s on a miss from note 7 onward)
```

- Right/wrong LEDs stay lit `LED_FEEDBACK_MS = 600` ms, timed with `millis()`.
- `PUMP_FROM_STEP = 7`, `PUMP_MS = 1000`, `MAX_FAILS = 10` → death tune.
- Victory / death / spray playback is intentionally **blocking** (TODO #9): the
  game is meant to pause while a tune or the spray plays.

## Buzzer

- `tone()` — key notes and short feedback tones (non-blocking).
- `buzz()` — a bit-banged square wave used by `playSong()` for the Mario /
  Underworld / death themes, blinking the on-board LED (D13) per note.
- In the Velxio build both paths route through `emuTone()` on **D11**; see
  [emulation/README.md](emulation/README.md) for why D8 beeps forever in the
  browser.
