# V3 hardware — game prototype

The V2 keyboard plus a feedback and actuator stage. Reconstructed from
[firmware/game-prototype/game-prototype.ino](firmware/game-prototype/game-prototype.ino).

## Pin map

| Pin | Direction | Role |
|---|---|---|
| A0–A6 | analog in | 7 fruit touch keys, each with a **220 Ω pull-up to +5 V** |
| D2 | out | **RED LED** — wrong note (220 Ω to GND) |
| D3 | out | **GREEN LED** — correct note (220 Ω to GND) |
| D4 | in | **GAME SELECT** push button, active-HIGH (+ 10 kΩ pulldown) — read at start-up |
| D5 | out | **RELAY** channel (initialised at boot; its firing code is commented out) |
| D8 | out | speaker / passive buzzer — key notes and the victory theme |
| D13 | out | on-board LED, lit while `buzz()` bit-bangs a melody note |
| 5V / GND | — | rails; the player holds a clip on **GND** |

## Bill of materials

| Component | Qty | Notes |
|---|---|---|
| Arduino Uno (2019) / Nano | 1 | Nano needed for key 7 (A6) |
| Fruit + alligator clips | 7 + 8 | 7 keys + 1 hand-held GND clip |
| 220 Ω resistors | 7 + 2 | 7 key pull-ups + one per LED |
| Red LED, green LED | 1 + 1 | D2 / D3, cathode to GND through 220 Ω |
| Push button | 1 | D4 game select, to +5 V with a 10 kΩ pulldown |
| 1-channel relay module | 1 | D5 (IN1), VCC/GND from the rails |
| Actuator (pump/motor) | 1 | on the relay's output — wired, never switched by this sketch |
| Speaker or passive buzzer | 1 | D8 |
| Breadboard + jumpers | 1 | |

⚠️ The button biasing (to +5 V with a 10 kΩ pulldown) is deduced: the sketch does
`pinMode(gameButton, INPUT)` with no internal pull-up and treats HIGH as
"pressed", which only works with an external pulldown. Same convention as V4's
RESTART.

## Sensing

Unchanged from V1/V2 — pins biased high through 220 Ω, a touch drags them down,
`4-sample average <= 1019`. The polarity flip to a +5 V clip happens in
[V4](../v4-water-pump/HARDWARE.md); the comparison table is in
[../../docs/HARDWARE.md](../../docs/HARDWARE.md).

## Feedback stage

```
 D2 ──▶|──[220 Ω]── GND     (red   = wrong note)
 D3 ──▶|──[220 Ω]── GND     (green = correct note)
```

Both LEDs are cleared after a timeout counted in **loop iterations** (not
`millis()`), which is why the feedback feels different on different boards — V4
switched to a real 600 ms `millis()` window.
